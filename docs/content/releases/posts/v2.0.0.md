# 2.0.0 - Release Highlights

- Deprecated method dev.galasa.selenium.IFirefoxOptions.getBinaryOrNull() has been removed. 

## Changes affecting the Galasa Service

- **`@DoNotRunInParallel`**: A test class can now be marked with the `@DoNotRunInParallel` annotation (`dev.galasa.DoNotRunInParallel`) so that the Galasa Service never runs more than one run of that class at a time, across the whole ecosystem. Use it for tests that cannot safely run alongside another run of themselves, for example because they depend on a resource that cannot be shared. See [Writing test classes](../../docs/writing-own-tests/writing-test-classes.md#preventing-a-test-class-from-running-in-parallel) for an example.
  - The requirement comes only from the annotation, through the test catalog of the test stream. The catalog entry for an annotated class contains `isSerial: true`, and the service reads it when runs are submitted. Nothing is passed when the runs are submitted, so a tag or an override cannot make a test serial or stop it being serial. After adding the annotation, the test catalog for the stream must be rebuilt from the test bundle.
  - While a run of the class is active, other runs of the same class stay `queued`. One of them is allocated when the active run finishes, is cancelled, or goes to `waiting`. A run in the `waiting` state does not hold the class, and it takes it again when it is requeued. Runs of other test classes, including other classes with the annotation, are not affected.
  - A class is held by a run until that run releases it. If a run finished without releasing it, the next run of the class takes it over, and this is logged at `INFO` level by the engine controller. A run which is `queued`, `waiting` or `allocated` is not treated as finished.
  - The annotation is not applied to shared environment runs.
